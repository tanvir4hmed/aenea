# Architecture Status

The implementation target is an evidence-first vertical slice: web simulator and command center -> Aenea application/MCP tools -> IncidentBridge normalization -> incident timeline and deterministic policy -> virtual actions, with Strands + Bedrock hosted on AgentCore Runtime and DynamoDB persistence.

The [final architecture diagram](architecture/01_aenea_architecture_overview_final.png) is the unchanged v1 design baseline selected for implementation. Its Ring/vendor labels denote simulated source/action categories in the Alexa+ demo, not working vendor integrations. The text documentation and verified deployed configuration govern implementation details.

Camera/doorbell, sensor, weather, household and device events are synthetic and visibly labeled. They still enter the real hosted backend through HTTP. No Ring API, official Ring simulator, Ring credentials, physical Alexa or physical IoT device is required.

Simulation Studio defines state/repeat profiles; Command Center starts durable runs. A minute-tick Lambda publishes through the same ingress processing. DynamoDB tracks run ownership, pending identities, per-incident simulation reservations and material briefings. Location-scoped registered outputs replace global virtual permissions. Alexa+ and History consolidate the retired Household/Handoff pages while retaining historical records and read-only MCP compatibility. No responder integration is implied.

The workspace refresh adds tenant-owned location/device catalogs, evidence revisions and transactional review/action guards to the existing storage and Lambda boundaries. Its historical Phase 8 added scheduled cleanup and deletion markers. The [automatic incident engine](automatic-incidents.md) now adds atomic location/hazard routing, human resolution and complete paged evidence with bounded 32-event model context; there is no 20-signal incident-total limit. These refinements remain inside the existing diagram's services. Earlier [workspace details](workspace-refresh.md) are historical where superseded.

Separate Terraform reasoner and MCP layers own AgentCore runtimes. The reasoner has no database/device authority. MCP exposes eight tools backed by the private tools Lambda; new person reporting is retired. Both paths share incident records and deterministic execution. Optional text intents select only status/timeline/acknowledgment, never free-form device control. See [current behavior and migration](state-driven-coordination.md), [MCP](alexa-mcp.md) and [verification](source-verification.md). Historical deployment dates do not establish acceptance of this source version.

Incident reads separate live state from historical pagination on the existing `GET /incidents/{id}/timeline` route. `view=status` omits the general audit-page query while retaining fresh incident/revision checks, latest assessment, active devices, actions, notes and practice budget. `view=records` returns only the requested timeline page and cursor, without reconstructing current state. Omitting `view` retains the combined response for older clients. Both views remain household-scoped and reject deleted incidents. The frontend requests records on demand; receiving a historical page never changes current-state freshness or action eligibility. See [usability and loading changes](usability.md).
